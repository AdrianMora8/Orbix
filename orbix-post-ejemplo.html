Introducción: por qué documentamos así

Este artículo es un ejemplo completo para probar todo lo que soporta el editor de ORBIX Studio: títulos, subtítulos, listas, tablas, código, imágenes, video y más. Podés borrar las secciones que no necesites y quedarte solo con la estructura.

Un párrafo puede tener texto en negrita, texto en cursiva y código en línea combinados sin problema.

  • ORBIX Studio construye software con estándares reales.
  • Cada entrada del blog documenta una decisión técnica concreta.
  • El objetivo es que otro integrante del equipo pueda retomar el trabajo sin perderse.

  1. Front-end en React + TypeScript.
  2. Backend as a service con Firebase (Auth, Firestore).
  3. Imágenes servidas desde Cloudinary.

Cómo configuramos el entorno local

Estos son los pasos mínimos para levantar el proyecto en una máquina nueva:

git clone https://github.com/orbix-studio/orbix
cd orbix
npm install
cp .env.example .env
npm run dev

Si todo salió bien, el sitio queda disponible en http://localhost:5173.

Variables de entorno necesarias

VariablePara qué sirve
VITE_FIREBASE_API_KEYAutenticación con el proyecto Firebase
VITE_CLOUDINARY_CLOUD_NAMESubida de imágenes
VITE_CLOUDINARY_UPLOAD_PRESETPreset unsigned de Cloudinary

Modelo de datos en Firestore

Usamos cuatro colecciones principales:

  • posts: artículos del blog, con status draft o published.
  • team: información del equipo (a futuro).
  • messages: mensajes recibidos desde el formulario de contacto.
  • users: cuentas del equipo con acceso al panel.

Reglas de seguridad, en resumen

Los posts publicados son públicos para leer; solo un usuario autenticado puede escribir. Los mensajes se pueden crear pero no leer desde el cliente.

Ejemplo de flujo de publicación

Así es como un integrante del equipo publica un artículo nuevo:

  1. Entra a /admin/login y se autentica.
  2. Crea un post nuevo desde el dashboard.
  3. Escribe el contenido con el editor (como este mismo ejemplo).
  4. Sube una imagen de portada.
  5. Guarda como borrador o publica directamente.
kubectl get pods -n orbix-demo
kubectl logs deployment/orbix-web -n orbix-demo
